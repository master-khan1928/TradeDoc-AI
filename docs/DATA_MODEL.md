# Модель данных: что где лежит и сколько живёт

**Серверной базы данных нет, и она не нужна.** Сервер ничего не хранит между запросами: файл и текст документа живут
в оперативной памяти только на время ответа. Это сильная сторона: на сервере нечего утечь, нечего резервировать и
нечего удалять по сроку. Если когда-нибудь понадобится серверное хранение (общий каталог правил, статистика), план
для Postgres/Supabase описан ниже, но сейчас он **не реализован**.

## Сервер (память процесса)

| Что | Где в коде | Срок | Содержит документ? |
|---|---|---|---|
| тело запроса `/api/read`, `/api/check` | `scripts/server.mjs` | время запроса | да, только в памяти |
| кэш результатов чтения бесплатной моделью | `lib/extract/limits.js` (`extractionCache`) | до 30 минут, до 200 записей | поля и цитаты **синтетических** документов; только бесплатные провайдеры; `LLM_CACHE=off` выключает |
| лимитер частоты запросов к модели | `lib/extract/limits.js` | 1 минута окна | нет, только метки времени |
| лимит запросов по IP | `scripts/server.mjs` | 1 минута окна | нет, только IP и счётчик |
| признак «json_schema не принят» | `lib/extract/meta.js` | до перезапуска | нет |
| журнал (stdout) | `scripts/server.mjs` | по настройкам хостинга | нет: строка запуска и служебные события |

## Браузер пользователя (localStorage)

| Ключ | Что | Схема | Лимиты | Удаление |
|---|---|---|---|---|
| `td:cases:v1` | «дело груза»: рейс, дата выезда, версии документов (тексты), история проверок с цитатами | `{ v: 1, cases: [{ id, title, departure, createdAt, updatedAt, docs: { invoice/packing/cmr: [{ v, at, text, origin, name, kind, extraction? }] }, checks: [{ at, versions, changed, mode, passed, total, findings, unsure }] }], current }` | 20 дел, 10 версий на документ, 50 проверок на дело, не больше 2 МБ всего | «Удалить дело», «Удалить все мои данные» |
| `td:consent` | дата редакции принятого согласия | строка `ГГГГ-ММ-ДД` | | «Удалить все мои данные» |
| `td:lang` | язык интерфейса | `ru`/`en`/`kk` | | «Удалить все мои данные» |
| `td:draft:v1` | черновик: тексты полей документов текущего дела до проверки | `{ caseId, docs: { invoice, packing, cmr } }` | до 40 000 знаков на документ | после успешной проверки; «Удалить все мои данные» |

Чтение защищено: версия схемы (`v: 1`, другая версия не читается), проверка каждого дела и каждой версии
(повреждённое отбрасывается, остальное открывается), `try/catch` на каждом обращении (приватный режим и запрет
хранения не ломают страницу), лимит размера при записи. Код и тесты: `public/case-store.js`, `test/case.test.js`.

## Если понадобится серверная БД (не сделано)

Postgres или Supabase; миграции в репозитории; политика доступа на уровне строк (RLS) на каждой таблице; только
метаданные, никаких документов; минимальные поля; автоудаление по сроку; журнал действий без персональных данных;
резервные копии; отдельные роли на чтение и запись; только параметризованные запросы; ключ `service_role` только на
сервере, никогда в браузере.
