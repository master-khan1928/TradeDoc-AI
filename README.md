# TradeDoc AI

Проверка комплекта торговых документов (инвойс, упаковочный лист, CMR) **до выезда машины к границе**.
Код сверяет цифры и названия, у каждого замечания есть цитата и страница. Если ошибка у партнёра, система
готовит письмо с просьбой подтвердить верное значение. **Значений она не предлагает никогда.**

> Справка и черновики, не таможенная консультация. Все документы в примерах синтетические, компании вымышленные.

## Чего сервис НЕ делает

Не подаёт декларации и не заменяет таможенного брокера или юриста; не даёт юридических советов; не гарантирует
прохождение границы; не предлагает «правильных» значений (только что и где написано, и просьбу подтвердить);
не хранит документы на сервере; не называет результат работой Meta, пока Meta не подключена; не пишет «найдено
100%». Базы данных на сервере нет и не нужно: документы живут только в памяти запроса, «дело груза» хранится в
браузере пользователя ([docs/DATA_MODEL.md](docs/DATA_MODEL.md)). Это сильная сторона: на сервере нечего утечь.

Юридические черновики (ru/kk/en, **не проверены юристом**): [docs/legal/](docs/legal/), поток данных и
маскирование: [docs/legal/DATA_FLOW.md](docs/legal/DATA_FLOW.md), риски и вопросы юристу:
[docs/legal/RISKS.md](docs/legal/RISKS.md). Безопасность: [SECURITY.md](SECURITY.md),
[docs/THREAT_MODEL.md](docs/THREAT_MODEL.md). Лицензии: [THIRD_PARTY.md](THIRD_PARTY.md). Деплой: [docs/DEPLOY.md](docs/DEPLOY.md).

```bash

npm run bench     # бенчмарк на синтетических комплектах (MOCK)
npm run compare   # сравнение с одним запросом к модели (только с META_API_KEY)
npm run probe     # проверка подключения к модели одним запросом (только с META_API_KEY)
```

## Режимы ИИ (LLM_PROVIDER)

Провайдер выбирается одной переменной `LLM_PROVIDER`. Интерфейс у всех один: модель читает документ и
возвращает JSON по схеме, цитаты проверяет код, сверку делает код. Режим всегда виден на сайте и в отчёте.

| `LLM_PROVIDER` | Что читает | Ключ и модель | Статус |
|---|---|---|---|
| `mock` (по умолчанию) | разбор по шаблону «Метка: значение», **не ИИ** | не нужны | работает |
| `gemini` | Google Gemini через OpenAI-совместимый адрес `https://generativelanguage.googleapis.com/v1beta/openai` | `GEMINI_API_KEY`, `GEMINI_MODEL` | код написан и проверен на подделанных ответах; **с настоящим ключом не запускался** |
| `groq` | Groq, `https://api.groq.com/openai/v1`, модель по умолчанию `qwen/qwen3.8-27b` (изображения, JSON mode) | `GROQ_API_KEY`, `GROQ_MODEL` (необязательно) | то же |
| `openrouter` | OpenRouter, `https://openrouter.ai/api/v1` | `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` | то же |
| `meta` | Meta Model API | `META_API_KEY`, `META_MODEL`, `META_BASE_URL` | **слой подготовлен, ждём ключ**; без ключа не запускался |

Источники (проверено 03.11.2026): [Gemini, OpenAI-совместимый API](https://aistudio.google.com/docs/openai),
[Gemini, модели](https://aistudio.google.com/docs/models), [Groq, OpenAI-совместимый API](https://console.groq.com/docs/openai),
[Groq, изображения](https://console.groq.com/docs/vision), [OpenRouter, быстрый старт](https://openrouter.ai/docs/quickstart).
Что **не подтвердилось** по документации: стабильная модель Gemini с изображениями на входе (страница моделей не
указывает модальности стабильных моделей), поэтому модель Gemini в коде не зашита: задайте `GEMINI_MODEL` сами,
сверившись с AI Studio. Числа бесплатных лимитов (RPM/RPD) обе документации публично не дают и отправляют в личный
кабинет; у OpenRouter бесплатные модели в документации не названы.

Лимиты на нашей стороне: не больше `LLM_RPM` запросов в минуту (по умолчанию 10 для бесплатных провайдеров, 60
для Meta); при 429 один повтор с паузой по `retry-after` (не больше 10 с); затем резервный провайдер `LLM_FALLBACK`
(например, `groq`), если он настроен; иначе честное сообщение «лимит бесплатной модели исчерпан» и разбор по шаблону.
Для бесплатных провайдеров есть кэш по хэшу документа (в памяти, 30 минут, `LLM_CACHE=off` выключает): повторная
проверка того же синтетического комплекта не тратит лимит. Для Meta кэша нет.

> **Бесплатные тарифы: только синтетические документы.** Условия Google для бесплатных сервисов: Google использует
> отправленный контент для улучшения своих продуктов, его могут читать люди-рецензенты, и прямо сказано не
> отправлять конфиденциальную и персональную информацию ([условия Gemini API](https://aistudio.google.com/docs/terms)).
> Поэтому в режимах `gemini`, `groq`, `openrouter` сайт показывает баннер «демо-режим: не загружайте реальные
> документы», а сервер не отправляет в модель документ, в котором похоже есть реальные персональные данные
> (ИИН/БИН с верной контрольной цифрой, e-mail, телефон, IBAN, номер паспорта). Это эвристика, не гарантия.
> Фото до отправки проверить нельзя (своего распознавания нет): проверяется расшифровка, и при таких данных результат
> отбрасывается, но картинка к провайдеру уже ушла.

Переход на Meta, когда придёт ключ: `LLM_PROVIDER=meta`, `META_API_KEY`, `META_MODEL` (и `META_BASE_URL`, если адрес
другой), затем `npm run probe`. Не используйте модели с суффиксом `-contributor` с реальными документами.

## Режимы чтения

| Режим | Когда включается |
|---|---|
| MOCK | по умолчанию |
| META | заданы `META_API_KEY` **и** `META_MODEL` (и не стоит `AI_MODE=mock`) |

`META_BASE_URL` по умолчанию `https://api.meta.ai/v1` (формат OpenAI, `POST /chat/completions`, `response_format: json_schema`).
Идентификатор модели в коде не вшит и берётся **только** из `META_MODEL`: у Meta он меняется, проверьте актуальный
в документации и в личном кабинете.

> **Не используйте модели с суффиксом `-contributor` с реальными документами.** Meta может обучаться на запросах
> к таким моделям, а документы партнёров содержат коммерческие данные. Для реальных документов выбирайте модель
> без этого суффикса и проверьте условия обработки данных в документации Meta. Код модель не выбирает и не
> подменяет: что задано в `META_MODEL`, то и используется.
Если запрос к модели не удался, система честно возвращается к MOCK и показывает предупреждение с причиной (ключ, модель, лимит, сеть, таймаут, ответ не по схеме).
Что вернула модель, всё равно проходит проверку цитат: поле остаётся, только если цитата дословно есть на странице.

## Первый запуск с ключом (Windows, PowerShell)

С настоящим ключом проект **ещё не запускался**: всё ниже проверено только на подделанных ответах модели и на
локальной подделке сервиса. Ключ задаётся только на один сеанс PowerShell: не в файлы, не в репозиторий,
не через `setx` (он сохраняет навсегда).

1. Откройте PowerShell в папке проекта и один раз поставьте зависимость:
   ```powershell
   cd C:\путь\к\tradedoc
   npm install
   ```
2. Задайте переменные на этот сеанс. Ключ вводится скрыто и не попадает в историю команд:
   ```powershell
   $s = Read-Host -AsSecureString "META_API_KEY"
   $env:META_API_KEY = [System.Net.NetworkCredential]::new("", $s).Password
   $env:META_MODEL = "идентификатор-модели-из-документации-Meta"
   ```
   Для реальных документов не берите модель с суффиксом `-contributor` (см. «Режимы чтения»).
   Только если адрес API отличается от `https://api.meta.ai/v1`: `$env:META_BASE_URL = "https://…/v1"`.
   Если модель отвечает дольше 25 секунд: `$env:META_TIMEOUT_MS = "45000"`.
3. Проверьте подключение одним маленьким запросом на синтетическом документе:
   ```powershell
   npm run probe
   npm run probe -- --image
   ```
   Что выводится (ключ, тексты документов и ответ модели не выводятся никогда):

   | Строка | Что значит |
   |---|---|
   | `HTTP-статус: 200 (json_schema)` | модель ответила по строгой схеме |
   | `json_schema: НЕ поддерживается …; работает запасной режим` | сервис отклонил `response_format`, работает запасной режим «верни JSON» с той же проверкой цитат |
   | `Проверку цитат прошло: полей N из M` | сколько полей модели подтвердились дословной цитатой; для `--image` сверка идёт с расшифровкой самой модели |
   | `ключ не принят` (401/403) | неверный ключ или у ключа нет доступа к модели |
   | `неверный идентификатор модели` (404) | проверьте `META_MODEL` и `META_BASE_URL` |
   | `превышен лимит` (429) | подождите и повторите |
   | `сеть недоступна` | нет интернета или неверный `META_BASE_URL` |
   | `ответ не по схеме` | модель вернула не JSON; пришлите мне вывод probe (он без ключа и текстов) |
   | `запрос отклонён (400)` в режиме `--image` | возможно, модель не принимает изображения |

   Код выхода: 0 работает, 1 не работает, 2 не задан ключ или модель.
4. Запустите сайт в том же окне PowerShell (переменные живут только в нём):
   ```powershell
   npm start
   ```
   Откройте http://localhost:3000. Справа вверху должно быть «чтение: Muse Spark», а не «демо-чтение (MOCK)».
   Нажмите «Проверить комплект» на примере. Если появилось «ИИ недоступен … Причина: …», это та же причина,
   что показал бы probe; документы в этом случае прочитаны демо-разбором и это написано на странице.
   Если сервис не принял строгую схему, рядом будет пометка «запасной режим JSON».
   Загрузите фото документа (JPG/PNG): в колонке появится «С фото… подтвердите значения вручную».
5. По желанию небольшое сравнение с одним запросом: `npm run compare -- --errors 3 --clean 2` (20 запросов).
6. После работы закройте окно PowerShell или удалите ключ из сеанса: `Remove-Item Env:META_API_KEY`.

Как устроен запрос к модели: таймаут `META_TIMEOUT_MS` (по умолчанию 25 с), **не больше одного повтора** и только
при временных сбоях (429, 5xx, сеть, таймаут); при 401/403/404/400 повтора нет. Документы комплекта читаются
параллельно, поэтому проверка ждёт модель не дольше одного запроса с повтором; браузер ждёт сервер до 2 минут
и потом честно пишет, что ответ не пришёл. Запасной режим «верни JSON» включается только после явного отказа
сервиса от `json_schema` (HTTP 400/422 с упоминанием `response_format`/`json_schema`), запоминается до
перезапуска сервера, отмечается на сайте и одной строкой в логе сервера (без ключа и текстов).

## Загрузка файлов

`POST /api/read`, тело запроса: сами байты файла (не base64), тип документа можно передать в `?type=invoice|packing|cmr`.
Формат определяется по первым байтам файла, а не по имени.

| Вход | MOCK | META |
|---|---|---|
| PDF с текстовым слоем | текст извлекает код, дальше разбор по шаблону | текст извлекает код, поля читает модель, цитаты проверяются по тексту PDF |
| JPG / PNG / WEBP | ответ 422 `photo_needs_meta`: «для чтения фото нужен режим META» | модель получает картинку (`image_url`, data URI), возвращает `transcription` и поля; цитаты проверяются по `transcription` |
| TXT (UTF-8) | разбор по шаблону | поля читает модель |
| PDF без текста | 422 `pdf_no_text` | 422 `pdf_no_text` |
| больше 1,5 МБ | 413 `file_too_large` | 413 |
| другой формат | 415 `unsupported_format` | 415 |

Разбор фото браузер присылает обратно вместе с расшифровкой в `/api/check`, чтобы не звать модель второй раз.
Сервер ему не доверяет: оставляет только известную форму полей и заново проверяет каждую цитату по тексту.
Если текст поправили руками после загрузки, разбор фото не отправляется и документ читается заново как текст.

Не добавляйте ключ в репозиторий: только переменные окружения хостинга.

## Бенчмарк: что он измеряет и чего не измеряет

`npm run bench` всегда работает в MOCK (без ИИ) на **синтетических** комплектах с заранее известными ошибками:
14 типов ошибок по 10 комплектов, 60 чистых комплектов, 30 комплектов по 3 ошибки. Результат: `bench-results.json`.
Режимов два, на одних и тех же данных и ошибках:

| Режим | Документы | Что измеряет |
|---|---|---|
| `template` | формат «Метка: значение», который знает MOCK-разбор | только **логику сверки** (`audit.js`): чтение здесь заведомо идеальное |
| `dirty` | `lib/generate-dirty.js`: 3 шаблона (английский, русский, двуязычный), числа 1,234.50 / 1.234,50 / 1 234,50 / 1234.50, даты 2026-10-07 / 07.10.2026 / 07/10/2026, шапка с адресами, лишние строки, ошибки пробелов в метках, нумерованные графы CMR. У каждого документа комплекта свой шаблон | всю цепочку **MOCK**: разбор по шаблону + разбор чисел + сверку |

Результат на 25.10.2026 (`npm run bench`), после исправления разбора неоднозначных чисел:

| | template | dirty |
|---|---|---|
| одиночные ошибки найдены | 140/140 | 29/140 (до исправления 31) |
| чистые комплекты с ложным замечанием | 0/60 | **0/60** (до исправления 2/60) |
| ошибки в комплектах по 3 найдены | 90/90 | 12/90 |
| лишние замечания в комплектах с ошибками | 0 | **0** (до исправления 18) |
| пропуски на чистых комплектах из-за неоднозначного числа | 0 | вес брутто 10/60, вес нетто 10/60, места 2/60, нетто ≤ брутто 10/60 |

Как это читать:
- **Сверка работает, MOCK-разбор на «грязных» документах нет.** Большинство проверок на грязных документах
  пропускается: разбор по шаблону не узнаёт метки вроде «Invoice No.», «Вес брутто, кг», «4. Date of shipment»,
  «Seller / Продавец», строки товаров без «|». Проверка без данных честно пропускается, поэтому найдено мало.
  MOCK не ИИ и не предназначен для настоящих документов, под шаблоны генератора он не подгонялся.
- **Неоднозначные числа больше не угадываются.** Число с одним разделителем и ровно тремя цифрами после него
  («32.500», «1,080») без контекста получает статус «неоднозначно». Проверка с таким числом пропускается с причиной
  «формат числа неоднозначен, подтвердите вручную» и цитатой; ни значение, ни «правильный» вариант не называются.
  Контекст берётся только из того же документа: если в нём есть однозначные числа (1.234,50, 15,00, 1.234.567)
  и все они указывают на один десятичный знак. Даты, коды ТН ВЭД и телефоны контекстом не считаются; при
  противоречии контекста нет. Явное расхождение между однозначными числами по-прежнему даёт замечание.
  «28 500,000» однозначно: тысячи уже разделены пробелом, значит запятая десятичная (28 500).
  Цена исправления: 2 ошибки из 140 теперь не находятся, а пропускаются как требующие подтверждения.
- Попутно исправлено: определение типа принимало «к инвойсу №» в упаковочном листе за заголовок инвойса.

Чего бенчмарк **не** измеряет: чтение моделью (он всегда в MOCK), настоящие PDF и фото, документы реальных
партнёров. Генератор всё равно наш, поэтому даже `dirty` проще жизни: нет печатей, рукописных пометок, переносов
строк внутри полей, ошибок распознавания.

## Сравнение: наша цепочка против одного запроса к модели

`npm run compare` (код: `scripts/compare.mjs`, `lib/compare.js`). **Работает только с ключом**: без `META_API_KEY`
и `META_MODEL` честно пишет «нужен META_API_KEY» и выходит с кодом 2. **С реальной моделью не запускался**,
логика подсчёта проверена тестами на подделанных ответах модели.

На одних и тех же «грязных» синтетических комплектах (по умолчанию 20 с 1–3 ошибками и 10 чистых):

| Сторона | Как работает | Запросов на комплект |
|---|---|---|
| наша цепочка | модель читает каждый документ по схеме, код проверяет цитаты и делает сверку | 3 |
| один запрос | все три документа и просьба «найди расхождения», ответ: категория, документ, цитата, описание. Кода сверки нет | 1 |

Обе стороны используют одну модель, `temperature 0` и одни и те же тексты. Базовому варианту даём список
категорий проверок: без него его ответы нельзя сопоставить с известными ошибками (это помогает ему, а не мешает).

Таблица результата: внесённых ошибок найдено; ложных срабатываний (замечаний вне внесённых ошибок и их законных
последствий, например неверная сумма строки ломает и итог счёта); чистых комплектов с замечаниями; сколько замечаний
имеют цитату, которая дословно есть в документе. Комплект, на котором запрос к модели не удался, в счёт не идёт,
а число сбоев выводится отдельно. В `compare-results.json` пишутся только числа и seed, тексты документов не сохраняются.

Ограничения сравнения: синтетические документы, один прогон без повторов, одна модель, один вариант промпта
для базового варианта. Это сравнение подходов на наших данных, а не оценка качества на реальных документах.

## Приватность

Сервер документы не сохраняет: файлы и текст обрабатываются в памяти, ничего не пишется на диск, в базу и в логи.

«Дело груза» хранится **только в браузере пользователя** (localStorage, ключ `td:cases:v1`): тексты документов,
их версии, имена файлов и история проверок с цитатами. На сервер дело не отправляется. Кнопка «Удалить всё»
стирает все дела на этом устройстве, «Удалить дело» только текущее. Если браузер не разрешает хранение
(приватный режим) или место закончилось, проверка работает, а страница честно пишет, что дело не сохранится.
На общем компьютере дело увидит любой, кто откроет сайт в этом же браузере: удаляйте дела после работы.
