# TradeDoc AI

Проверка комплекта торговых документов (инвойс, упаковочный лист, CMR) **до выезда машины к границе**.
Код сверяет цифры и названия, у каждого замечания есть цитата и страница. Если ошибка у партнёра, система
готовит письмо с просьбой подтвердить верное значение. **Значений она не предлагает никогда.**

> Справка и черновики, не таможенная консультация. Все документы в примерах синтетические, компании вымышленные.

## Что сделано и что нет (честно)

| Часть | Статус |
|---|---|
| 13 проверок кодом (суммы, веса, места, названия сторон, даты, HS-код, ссылка на инвойс) | работает, проверено автотестами (всего 23) |
| Сравнение названий: кириллица / латиница / узбекская латиница, юр. форма не важна | работает |
| Цитата и страница у каждого замечания; поле с выдуманной цитатой отбрасывается | работает, есть тест |
| «Инспектор»: вопросы по правилам каталога; нет правила, нет вопроса | работает, **правила демонстрационные** (`needs_review`, без источников) |
| Письмо партнёру (RU / EN), только факты | работает; письма на казахском, узбекском, китайском не сделаны |
| Сайт: примеры, правка текста и повторная проверка, подсветка цитаты в документе | работает |
| Загрузка файлов на сайте: перетаскивание и выбор, до 1,5 МБ, каждый файл отдельным запросом (`POST /api/read`) | работает, проверено тестами и в браузере |
| PDF с текстовым слоем: текст извлекает код (библиотека unpdf), в памяти, **без ИИ** | работает и в MOCK; проверено на синтетических PDF, на настоящих PDF партнёров не проверялось |
| Тип документа (инвойс / упаковочный лист / CMR) по содержимому, если не указан | работает (ключевые слова, код); если неоднозначно, система не угадывает и просит выбрать колонку |
| Фото и сканы (JPG, PNG, WEBP): модель возвращает дословную расшифровку `transcription`, цитаты проверяются по ней | код написан, проверен **только на подделанных ответах модели**; с реальным ключом **не запускался** |
| Чтение текста документов **моделью** через Meta Model API | код написан (`lib/extract/meta.js`), **с реальным ключом не запускался** |
| Чтение документов в режиме MOCK | разбор по шаблону «Метка: значение», **это не ИИ** |
| PDF-скан без текстового слоя | **не поддерживается**: система просит загрузить страницы как фото (рендер PDF в картинку потребовал бы ещё одну зависимость) |

Поля, прочитанные с фото, помечаются на сайте «прочитано с фото, подтвердите вручную»: расшифровку делает модель,
и проверка цитат защищает только от расхождения между полем и расшифровкой, а не от ошибки самой расшифровки.

## Запуск

```bash
npm install       # одна зависимость: unpdf (MIT, бесплатная) для текстового слоя PDF
npm test          # 23 теста
npm run bench     # бенчмарк на синтетических комплектах
npm start         # http://localhost:3000   (PORT из окружения)
```

Нужен Node 20 или новее. Единственная зависимость: `unpdf` 1.8.1 (версия зафиксирована точно).

## Режимы чтения

| Режим | Когда включается |
|---|---|
| MOCK | по умолчанию |
| META | заданы `META_API_KEY` **и** `META_MODEL` (и не стоит `AI_MODE=mock`) |

`META_BASE_URL` по умолчанию `https://api.meta.ai/v1` (формат OpenAI, `POST /chat/completions`, `response_format: json_schema`).
Идентификатор модели в коде не вшит: у Meta он меняется, проверьте актуальный в документации и в личном кабинете.
Если запрос к модели не удался, система честно возвращается к MOCK и показывает предупреждение.
Что вернула модель, всё равно проходит проверку цитат: поле остаётся, только если цитата дословно есть на странице.

## Загрузка файлов

`POST /api/read`, тело запроса: сами байты файла (не base64), тип документа можно передать в `?type=invoice|packing|cmr`.
Формат определяется по первым байтам файла, а не по имени.

| Вход | MOCK | META |
|---|---|---|
| PDF с текстовым слоем | текст извлекает код, дальше разбор по шаблону | текст извлекает код, поля читает модель, цитаты проверяются по тексту PDF |
| JPG / PNG / WEBP | ответ 422 `photo_needs_meta`: «для чтения фото нужен режим META» | модель получает картинку (`image_url`, data URI), возвращает `transcription` и поля; цитаты проверяются по `transcription` |
| TXT (UTF-8) | разбор по шаблону | поля читает модель |
| PDF без текста | 422 `pdf_no_text` | 422 `pdf_no_text` |
| больше 1,5 МБ | 413 `file_too_large` | 413 |
| другой формат | 415 `unsupported_format` | 415 |

Разбор фото браузер присылает обратно вместе с расшифровкой в `/api/check`, чтобы не звать модель второй раз.
Сервер ему не доверяет: оставляет только известную форму полей и заново проверяет каждую цитату по тексту.
Если текст поправили руками после загрузки, разбор фото не отправляется и документ читается заново как текст.

Не добавляйте ключ в репозиторий: только переменные окружения хостинга.

## Как устроено

```

lib/audit.js   13 проверок, чистый код, ИИ не участвует
lib/normalize.js  транслитерация и сравнение названий сторон
lib/inspector.js  вопросы по правилам; data/rules.demo.json
lib/letters.js    письмо партнёру, без предложения значений
lib/generate.js   синтетические комплекты с известными ошибками (14 типов)
lib/files.js      формат файла по сигнатуре, текст PDF (unpdf), лимит 1,5 МБ
lib/upload.js     один файл -> документ (PDF, фото, текст)
lib/doctype.js    тип документа по содержимому

```

## Бенчмарк: что он измеряет

`npm run bench` вносит по одной известной ошибке 14 типов в синтетические комплекты (по 10 на тип), проверяет
60 чистых комплектов на ложные срабатывания и 30 комплектов по 3 ошибки. Результат: `bench-results.json`.

**Важно.** Комплекты создаёт тот же код, который задаёт формат документов, а читает их MOCK-разбор по шаблону.
Поэтому бенчмарк проверяет **логику сверки**, а не качество чтения настоящих PDF и фото моделью. Высокий процент
здесь не доказывает качество на реальных документах. Честное сравнение с обычным чатом и замер на реальных
документах (с разрешением владельцев, без коммерческой тайны) ещё предстоит сделать.

## Приватность

Документы не сохраняются: сервер обрабатывает файлы и текст в памяти и ничего не пишет на диск, в базу и в логи.
Файл, загруженный на сайте, живёт только в памяти вкладки браузера.
